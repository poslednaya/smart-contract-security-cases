# Where to find more published smart contract security reports

## Highest priority

1. [Code4rena reports](https://code4rena.com/reports): public contest reports; often comprehensive valid findings with original researcher attribution. Ideal for finding diverse DeFi cases.
2. [Cantina](https://cantina.xyz/): search competition pages and publicly disclosed findings; visibility varies by engagement.
3. [Pashov Audit Group reports](https://github.com/pashov/audits): many protocol-focused public engagements with technical findings.
4. [Trail of Bits reports](https://trailofbits.com/reports/): substantial professional review PDFs across complex blockchain systems.
5. [OpenZeppelin security research](https://www.openzeppelin.com/research): public in-depth audits with technical breakdowns.
6. [yAudit report catalog](https://reports.yaudit.dev/): DeFi-specific auditor reports, including ERC-4626, lending and vault issues.

## Additional sources

- [Cyfrin CodeHawks](https://codehawks.cyfrin.io/): useful for accessible competition findings; check public vs private competition access.
- [Sherlock public reports archive](https://github.com/sherlock-protocol/sherlock-reports): historic completed engagements, many PDFs.
- [Solodit](https://solodit.cyfrin.io/): discovery/search index for previously disclosed findings; always trace back to the original report and judgement.
- [0xSimao findings database](https://0xsimao.com/findings): annotated researcher notes; public visibility varies.
- [Centrifuge audit list](https://developer.centrifuge.io/developer/security/audits/): example of a protocol collecting 30+ reports from many auditing firms in one place.

## Selection criteria for a high-value case

- Public **final** report or judge outcome confirming validity and severity.
- Mechanism can be explained with a minimal state transition or math error.
- The issue can be tied to an invariant, bytecode-level behavior, or SMT-friendly verification question.
- Prefer diverse classes (state/accounting, price/oracle, initialization, authorization, cross-chain, precision).
- Original author's work is cited, while new tests/reproductions (if any) are explicitly distinguished.

Do **not** infer final severity from a submitter's title or from unreviewed GitHub findings. Do not copy another researcher's full report verbatim.
